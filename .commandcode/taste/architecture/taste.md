# Architecture

- Prefers the backend as the single source of truth and avoids duplicating business rules or state in the frontend (e.g., cart must not live in Zustand/localStorage). Confidence: 0.9
- Never treats client-side calculations (price, total, credit) as financial authority; the frontend only displays server-resolved values. Confidence: 0.9
- Handles monetary values safely and never trusts prices or totals sent by the client. Confidence: 0.9
- Reuses the existing stack (TanStack Query, Zustand, Zod, Tailwind/shadcn, next-intl) instead of introducing a new design system, UI library, or state architecture. Confidence: 0.9
- Converts backend errors (RFC7807) into useful messages without hiding the error code/type when needed for diagnosis. Confidence: 0.85
- Prefers a layered backend architecture (router → application/use case → domain → repository) and preserves it rather than broad refactoring. Confidence: 0.9
- Uses Decimal (never float) for money, weights, and tax values, with deterministic rounding (e.g., ROUND_HALF_UP). Confidence: 0.9
- Maintains tenant isolation / RLS on multi-tenant data. Confidence: 0.85
- Preserves RBAC, database transactions, and idempotency when applicable. Confidence: 0.8
- Reuses existing enums/tables before creating new ones and only adds migrations when truly necessary. Confidence: 0.85
- Exposes API endpoints only when the frontend/backend workflow actually needs them (no speculative APIs). Confidence: 0.8
- Never trusts weight sent by the frontend; computes shipping weight from catalog weight × quantity on the backend. Confidence: 0.9
- Keeps tax calculation, invoice generation, and payment clearly separated (tax calculation is a pure function with no persistence or credit movement). Confidence: 0.85
- Does not invent fiscal legislation, tax rates, or compliance claims; keeps tax as an explicit deterministic simulation and documents the missing fields/contracts instead of a large schema change. Confidence: 0.85
- Does not alter approved contracts without necessity. Confidence: 0.8
- Prefers a transactional outbox for reliable async notification/event publication (written in the same transaction as the triggering business event), consumed by a Celery/RabbitMQ worker. Confidence: 0.85
- Implements deletion of personal data (LGPD) as anonymization that preserves rows and financial/fiscal/audit records, rather than hard deletion that breaks referential integrity or silently drops retained data. Confidence: 0.85
- Does not claim full legal/LGPD compliance; validates and reports only the documented technical privacy requirements. Confidence: 0.8
- Exposes Prometheus metrics for critical flows with low-cardinality labels only, never including personal data or business identifiers (user/company/order ids) as labels. Confidence: 0.8
- Makes webhook/event handling idempotent by uniqueness on (provider, event_id) plus an explicit state machine that rejects out-of-order or invalid transitions. Confidence: 0.8
- Avoids SECURITY DEFINER database functions for platform-admin/cross-tenant operations; prefers direct UPDATE statements scoped by an explicit TenantContext so RLS still applies instead of a function that bypasses tenant isolation. Confidence: 0.8
- Detects whether an UPDATE affected a row via `RETURNING` + `.first()` rather than relying on `rowcount`. Confidence: 0.6
- Treats search engines/indexes as derived, non-authoritative data: the transactional database stays the single source of truth, and search hits are hydrated with authoritative fields on read. Confidence: 0.8
- Avoids duplicating modules, endpoints, indexes, or configuration; extends the existing ones instead of adding parallel implementations. Confidence: 0.8
- Treats non-critical dependencies (search engine, etc.) as optional: the application must start even when they are down, degrading gracefully with a logged warning instead of failing startup. Confidence: 0.8
- Places external integrations behind an application-layer port with an infrastructure adapter, so interface/application layers never speak the vendor's DSL. Confidence: 0.8
- Separates application health from external-dependency health (distinct probe/route), so a non-critical dependency being down does not fail readiness. Confidence: 0.75
- Never indexes prices (individualized/consultive) or personal/sensitive data into a shared search document; only public catalog fields are indexed, and price ordering stays out of scope when it cannot be shared safely. Confidence: 0.8
- Uses versioned indexes behind a stable alias (reads and writes go through the alias), swapping the alias atomically on full reindex and keeping the previous version for rollback; reindexing is repeatable and count-validated. Confidence: 0.75
- Keeps bounded contexts isolated (import-linter): communicates across modules through ports/parameterized SQL rather than importing another module's ORM models. Confidence: 0.75
- Applies external versioning (e.g., version derived from updated_at) so stale or out-of-order events cannot overwrite newer state; index upserts are idempotent. Confidence: 0.7
- Reconciles derived data against its source (repairing missing/orphan/stale records) periodically or on demand, not relying solely on background tasks. Confidence: 0.65
- Distinguishes a valid empty result from an infrastructure failure: never converts a failed query into a silent empty success — degrades to a fallback and surfaces a proper error (e.g., 503) when all engines fail. Confidence: 0.75
- On read, drops and logs stale/defunct entries returned by a derived index (e.g., records no longer valid in the source of truth) instead of returning them. Confidence: 0.7
- Keeps derived auxiliary data (e.g., embeddings) in a separate table linked by FK to the source entity, never altering the source table, so it can be regenerated/reindexed independently. Confidence: 0.7
- Imports heavy optional runtime dependencies lazily inside the infrastructure adapter (never at module/app import time) so a missing dependency degrades gracefully instead of blocking startup. Confidence: 0.75
- Runs independent optional retrieval paths (lexical + semantic) in parallel and fuses their results, then hydrates authoritative data from the transactional DB; reports the actual execution mode used (e.g., hybrid vs lexical vs fallback) rather than only the intended one. Confidence: 0.7
- Bakes heavy model/ML artifacts into the image build or mounts them via volume (never downloads them at request time), and documents the expected memory/latency impact so the system can degrade gracefully if the host cannot afford them. Confidence: 0.7
- Emits structured logs for critical flows including the real mode and latency, while excluding sensitive values (e.g., the searched term, tenant, or secrets). Confidence: 0.7
- Creates database extensions in the bootstrap step under the superuser rather than inside migrations: the migration role is NOSUPERUSER and cannot create non-trusted extensions (e.g., pgvector), so migrations only consume them and downgrades never drop shared extensions. Confidence: 0.8
- Keeps `alembic check`/autogenerate green for raw-SQL-managed objects: registers custom types (e.g., pgvector's `vector`) for reflection and excludes derived tables/indexes created by raw SQL from autogenerate instead of modeling them in the ORM. Confidence: 0.75
- Writes raw SQL with explicit `CAST(...)` on parameters, including those used in `IS NULL` comparisons and LIMIT/OFFSET, because asyncpg cannot infer their types (`AmbiguousParameterError`). Confidence: 0.75
- Uses a single-token `asciifolding` in Elasticsearch keyword normalizers (never `preserve_original`, which emits two tokens and makes keyword fields silently reject indexing). Confidence: 0.65
- Configures timeouts and retries per use case instead of sharing one client setting: the interactive path (search/autocomplete) gets a short timeout and no retries so it falls back fast, while indexing/reindex/reconcile/bootstrap keep longer timeouts and their own retries; all exposed as separate configurable variables. Confidence: 0.7
- Adds a simple configurable circuit breaker on the interactive path (after N consecutive failures, skip the failing dependency for T seconds and retry automatically), but only if it fits in a few lines with tests and configurable values. Confidence: 0.65
- Treats per-document bulk/indexing rejections as a visible failure: records a redacted reason sample, exits non-zero, marks affected events as failed/retryable, and refuses to swap the alias on any rejection or count divergence beyond a configurable tolerance (default zero), keeping the previous index serving. Confidence: 0.75
- Never writes files to disk at runtime (hosting disks are ephemeral, e.g., Render); static assets are versioned in the repo/build and served by the application (e.g., mounted static directory) so they survive redeploys. Confidence: 0.75
- Serves product/UI assets with a single, testable resolution rule (own asset > category default > generic placeholder) and returns both the resolved URL and an accessibility alt text. Confidence: 0.65
- Prefers creating original assets (e.g., original flat SVG illustrations) instead of using third-party images, brands, logos, or stock libraries; documents that the assets are original to the project and replaceable later. Confidence: 0.7
- Keeps locale/translation resolution in the application or domain layer (pure, testable functions) and never in endpoint handlers; endpoints only resolve the requested locale (Accept-Language/`?lang=`, validated against the supported set, invalid -> default without error) and pass it through. Confidence: 0.85
- Prefers stored translations over per-request realtime translation within a phase: translations are persisted keyed by locale alongside the source, with stale detection via a source content hash; external/paid translation providers are not adopted without an explicit decision and the available options (auto-translation API, LLM, local OSS model) are documented with cost/quality/dependencies instead of being silently introduced. Confidence: 0.8
- Makes fallback per-field (not whole-object): a partial translation serves translated fields at the requested locale and falls back field-by-field to the source locale (pt-BR), returning both the effective `content_locale` delivered and a `fallback` flag per response. Confidence: 0.75
- For multilingual/RTL frontends, sets `dir="rtl"` + `lang` attributes and uses logical CSS properties (`margin-inline`, `padding-inline`, `inset-inline`) rather than physical left/right, with mirrored directional icons and an Arabic-capable font stack; uses `Intl` (never hardcoded tokens) for numerals, currency, and number formatting. Confidence: 0.75
- Flags machine/human-translated content as "not reviewed by a native speaker" and requires native-speaker review before any production use of translated catalog/UI text, documenting the gap as a blocking precondition. Confidence: 0.7
- Documents architectural decisions as a frozen "não reabrir" set within the phase: enumerates each rejected option with its trade-offs (cost, quality, dependencies) and only re-evaluates with new evidence or an explicit owner decision, rather than reopening decisions mid-implementation. Confidence: 0.75
- For multilingual seed/demo content, generates translations offline once, version-controls the assets next to the seed, loads them idempotently (re-running yields no duplicates/drift), and adds a preservation test asserting numbers/units/codes/SKUs match the source locale exactly (no invented claims, no brand/SKU translation). Confidence: 0.7
